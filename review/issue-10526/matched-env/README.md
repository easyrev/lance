# PR 1 的匹配环境复测

对比 base `cb8c25692` 和 pure-B `16e3c99b1`。使用四套新建匹配环境中的两套。四者复用现有扩展，未重新编译，所有读测使用 `LANCE_CPU_THREADS=64`。[导入 RSS 与扩展 SHA256](environment.md)

阶段 1 的 8 份数据文件与历史 SHA256 一致。四份复用上轮现存文件，其余四份以原生成器、输入、分批和写入设置重建。每个数据集运行 scan、重复 take(128) 和重复 take(1024)。每次重复 take 含 20 个调用，同一个 dataset 句柄与同一组排序行号。scan 每构建每组 7 个进程，take 每构建每组 5 个。先运行正式组，再在同一环境、同一构建中运行等样本量重复组，两组均按构建轮转。24 个用例，共 544 个独立计时进程。

- [正式组中位数、区间、百分比和判定](summary.md)
- [每构建和每指标的 A/A 差](aa.md)
- [超出噪声的指标及计数](classified.md)
- [样本审计](audit.txt)与[计时原始输出](timed-processes.tar.gz)

每项比较采用双方各自 A/A 中位数绝对差的较大值作为该比较的噪声参照。仅在中位数绝对差严格超过该值的两倍且两组 min–max 不相交时，按方向记为收益或回归。使用未舍入数据判定。

安装核对首次发现四套环境的 wheel RECORD 中含各自路径相关的命令启动器哈希。计时启动前确认这些元数据差异的文件实际哈希及启动器内容，仅本地路径不同，其余 site-packages 字节一致。四份 pip freeze 逐字节相同。首次门槛检查未产生计时样本。环境记录、数据哈希和命令见 [环境与脚本](environment-and-scripts.tar.gz)。原始输出压缩归档并解压逐字节核验。[交接单](handoff.md)

base → pure-B 的 96 项比较中，52 项收益、0 项回归、44 项在噪声内。单页对照的所有指标在噪声内。见 [全部判定](summary.md)。
