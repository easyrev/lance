## 未覆盖与实验解释限制

- **缺少一条把三个边界同时串起来的定向用例。** 继承的真实 late retry 用例通过 `execute_batches`，绕过 B 的 streaming 预读；继承的 EOF-stream fail-fast 用例使用 full schema，没有 late payload。本轮新增 Python tail-error/重复修改用例是 `conflict_retries(0)`。这些各自有区分力，但不能拼成“EOF/跨限 streaming source + FirstSeen + late payload + 成功冲突重试”已联合运行的证据。[late retry 实际入口](/Users/salamanca/workspace/personal/Lance/output/unified-9505-20261019/ports/DB/source/rust/lance/src/dataset/write/merge_insert.rs:17154)、[EOF stream fail-fast](/Users/salamanca/workspace/personal/Lance/output/unified-9505-20261019/ports/DB/source/rust/lance/src/dataset/write/merge_insert.rs:17169)、[本轮尾部错误用例](/Users/salamanca/workspace/personal/Lance/output/unified-9505-20261019/tests/test_merge_semantics.py:62)。这属于覆盖缺口，当前没有发现其背后的确定实现错误。
- **FirstSeen 跨预读停止边界、字节跨限与后台 spill 重放的联合 case 未确立。** 源码保留顺序、重建 tracker 和原 replay 授权，但没有本轮专门执行证据。默认 Fail 的跨限重复修改不能替代 FirstSeen winner 验证。
- **source 准备有真实成本及失败范围。** B 的 100 MiB/rows 上限不是硬 RSS 上限，越界整批和 backing buffers 可更大；无 batch/time 上限，慢源或空批长流可能长期停留在准备阶段。准备发生于 retry executor 计时之前，但在 harness `builder.execute` elapsed 之内。这是继承 B 的机制，不能归因于 DB 的 D 节点，也不能以 shared pool 抹去。
- **计划变化本身不构成失效。** EOF 统计与 D 的窄 target 可能改变 Auto 选边、分区、行序和 late Take 局部性；这是 DB 应被测量的组合效应。只要完整行 oracle 和 snapshot 检查成立，就不应要求 DB 与 D/B 使用相同计划来“保证公平”。因果归因应按实际计划拆分，见 [局部性假设](/Users/salamanca/workspace/personal/Lance/output/unified-9505-20261019/locality-hypothesis.md)。

当前没有足以要求停下构建、修改 frozen DB 或排除其结果的确定问题。联合边界若日后成为发布范围，应补定向测试；本轮仍以主任务正在执行的 DB Rust/Python suite、完整结果 oracle 和失败后 snapshot 验证判定运行事实。
