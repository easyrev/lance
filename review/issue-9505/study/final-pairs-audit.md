# 完整配对矩阵审计：87 次 execute

本记录验收五份 pairs plan 的 **87 次新执行、87 份独立完整值 oracle、29 个三轮组和 30 项预登记比较**。全部为 validated_success，没有缺格、reference、资源失败或剔除样本。pairs-v1-exit-code 为 0。这里的“完整”仅指这五份配对计划；**23 格 diagnostic 与远端 verify-files 尚未完成，不在本记录的验收范围内**，也不能据此宣布整体实验审计完成。之前的 [51 格 partial note](paired-audit-note.md) 保持不变。

新增 ordinary 的 36 格与此前 51 格均重新逐格检查：plan/freeze/harness SHA、actual imported identity、source/binary contract、variant environment、spec/initial snapshot、result 与 metrics 的全部共同字段、独立 validator 身份、source 日志、oracle 全用户字段/行数/action counts/版本、资源限制和 worker 命令、独立 TMPDIR、事件及 gate。五份 gate 的 planned/completed/status 集合与原始记录一致。

共核对 7,314 个 producer batch、31,862,175 行 source、1,470 个 oracle 用户字段 hash 和 174 个独立执行/验证 cgroup。producer 聚合、执行 RSS/TMP 采样峰值、cgroup memory.peak 及 OOM 事件差值均从原始记录重算吻合。每个 cgroup 从空进程组开始，memory.max=8 GiB、swap.max=0，无 timeout/OOM/cleanup_error。全部格使用 reader、hot、rewrite_rows；R_admission 配置 pool 为 256 MiB，其余为 1 GiB。use_index=False、conflict_retries=0 来自已冻结 harness。

本次只运行本地只读 Node 代码，没有 SSH、导入 Lance、运行实验、修改冻结文件或重扫 fixture。源码、扩展和 fixture 内容身份是冻结记录之间的比对，尚不替代远端文件本体的 hash 复核。逐字段值检查由原独立 U worker 完成，本次核对其报告、字段覆盖和身份。

## 普通场景中必须保留的代价

N_dense（90% 唯一 key 更新）中，D/CTX、DB/B、DP/P 的同 block 墙钟比率中位数分别为 **1.625570、1.681538、1.519803**，三个 block 的方向均为 late 更慢。D/DB 的 CPU 秒、RSS/cgroup 和逻辑读取量同时增加；DP/P 的 RSS 略降，不能把三组都概括成内存增加。

V_dense 的对应墙钟比率为 **1.060433、1.026585、1.037752**。墙钟差距较小，但 D 的 CPU 中位数为 6.583368 s，CTX 为 1.364507 s；DB 为 5.219832 s，B 为 1.258749 s。CPU 秒跨工作线程累计，可以大于墙钟耗时；这些 CPU 原值是必须单独报告的资源代价。下面不把独立 CPU 中位数相除包装成预登记配对统计。

V_dense 中 D/DB 的 RSS 中位数分别为 618.89/610.34 MiB，CTX/B 为 1033.17/963.66 MiB，体现 CPU 与内存交换。DP 的 CPU 中位数为 0.861692 s、RSS 482.31 MiB，P 为 1.072767 s、758.96 MiB；P/DP 的执行策略交互需要单独解释，不能直接沿用 D/CTX 的 CPU 结论。

普通场景全部 36 格的 physical read_bytes 为 0、采样 TMP 峰值为 0。N_dense 的 D/DB rchar 约 165 MB，early 候选约 5.61 MB。V_dense DB rchar 约 219.46 MB，高于 D 的约 181.05 MB，尽管 DB 墙钟更短。rchar 是逻辑读字节记录，syscr 是进程读类系统调用计数；均不能称为物理磁盘读取、Lance Take 次数或对象存储请求数。当前结果只支持 hot 合同。
