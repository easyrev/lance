A small partial-schema upsert could hold the whole target table in memory, outside any pool. The plan path built its hash join on the target scan, which DataFusion never swapped because the schema byte estimate makes wide rows look small. The scalar-index path full-joined its scan of the unindexed fragments, emitting every target row. Both scans used the scanner defaults, and the merge session ignored LANCE_MEM_POOL_SIZE.

The merge now runs under the configured pool, collects the source as the build side, joins only the rows it needs, and streams the target through a scan budgeted from the pool. The column-patch writer sorts under the same budget in one partition, so its sorter holds the whole pool instead of a per-core fair share too small for one batch.
