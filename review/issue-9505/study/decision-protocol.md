# 本轮实验的决策顺序

本记录在本轮任何性能样本产生前写入。候选的源码机制见 `cost-mechanism.md`，执行合同见 `harness/RUNBOOK.md`；这里约束扩展实验的理由，避免按结果移动判定标准。

1. 所有候选先通过完整字段、操作计数、条件和 NULL 的小型正确性门槛。资源失败必须独立重开 dataset 验证原快照未改变。任何错误值、错误计数或失败操作提交都先停止该候选的性能判断。
2. F16、Wn、Ws 在相同 1 GiB 配置 pool、8 GiB cgroup、Rows writer 和 reader 输入下运行存活检查。U 的实际执行 pool 无界；其配置值不冒充已生效的限制。U/F16 在本轮只运行一次，历史 OOM 不代替该测量。
3. R_admission 使用 256 MiB 配置 pool，检查固定 source build 的反向容量代价。F64 首先比较 D、DB，检验窄 target build 是否仍随行数失效，以及 EOF 统计是否提供出口；有尚未回答的问题才增加其他候选。
4. N_dense、V_dense 首先比较 CTX 与 D，分别覆盖普通整数遗漏列和长度变化的 Utf8/LargeBinary 遗漏列。两者都存活后做三轮随机顺序配对。原任务书建议的稳定超过 10% 回退仍视为需要解释的边界；不以别的格的大幅改善抵消。小绝对差值和轮间波动同时报告。
5. late_jump 的完整 API 测试记录进程和 cgroup 峰值；定向 Rust 测试保证物化器真的先见小值、再连续见大值。fixture 的源顺序或 scanner 批大小不能单独证明物化顺序。该实验检查软分块的边界，不以一次存活宣称 RSS 硬限。
6. 第一格冷读取选择 V_dense 的 CTX/D 对照，因为它最可能改变默认延后取列的选择。标签始终为“尝试驱逐后的本地读取”，并核对 mincore 和实际 read_bytes。若改变决策，再做同合同三轮配对；没有远端对象存储证据时不外推网络请求收益。
7. 根据存活和首轮结果，只给影响选择且双方可完成的格登记三轮配对。D/CTX 归因于 late payload 整体，DB/D 检查统计准备，DP/P 检查固定策略下的 late payload。B/DB 的差异还包含共享 context，不能全部归因于 late。
8. 若 CTX 在 1 GiB 下无法完成宽字段，先保留失败；只有需要区分纯上下文与 late 的延迟贡献时，才为 CTX/D 添加相同更大 pool 的存活与配对，不用失败时间算加速比。
9. 只在观察到高覆盖率的实际代价后考虑全局 row address 排序等替代实验。排序的潜在收益、语义和资源成本先见 `sort-alternative-notes.md`；现阶段未实现，不能提前列作最佳方案。
10. Columns writer 作为业务替代方案单独登记，不能混进相同 Rows 写入语义下的候选排名。P 的 indexed/Columns 外围改动保留其独立责任；若没有充分覆盖，不提出全面替代 #10077。

原始失败、慢样本、测试驱动异常和未完成计划全部保留。性能实验通过、综合方案更优、值得上游接纳是三个不同判断。本轮不创建或更新公开 PR；贡献形式由证据决定。
